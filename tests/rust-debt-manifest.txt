# The Rust suite's CLOSED DEBT INVENTORY.
#
# WHY THIS FILE EXISTS
# scripts/test-xfail.py reconciles `cargo test --list --ignored` against
# `cargo test --ignored`: it answers "is every declared failure still failing".
# It cannot answer "is the debt still declared", because BOTH of its sides are
# derived from the same listing, and a debt can leave that listing two ways:
#
#     delete the `#[ignore]` from a still-failing test   -> not listed
#     delete the test                                    -> not listed
#
# Either way the gate goes green having established nothing. That is the exact
# failure that let v0.3.0 ship a live silent miscompile under a green
# `make m1-exit`. tests/conformance-manifest.txt already solved this class for
# .pd fixtures by being a closed inventory; this is the same shape for the Rust
# tests, and scripts/test-xfail.py enforces it.
#
# FORMAT — 5 TAB-separated non-empty columns:
#   1 target      exactly as cargo prints it after `Running` (e.g. tests/e2e_test.rs)
#   2 test        the FULL module path cargo prints (e.g. tests::group::test_x)
#   3 class       owed | paid
#   4 owner       M1..M9 | unscheduled for `owed`; `-` for `paid`
#   5 diagnostic  literal text the failure must print, for `owed`; `-` for `paid`
#
# THE TWO CLASSES
#   owed   the test must exist, must still be #[ignore]d as XFAIL, its
#          #[ignore] owner must MATCH column 4, and when it fails the output it
#          printed must CONTAIN column 5. Retagging one of the first two now
#          disagrees with the other instead of silently moving a debt.
#   paid   the test must exist and must NOT be #[ignore]d any more. Whether it
#          PASSES is the ordinary suite's job — which is why `make m1-exit` runs
#          the ordinary suite as inventory 3 of 4. A `paid` row over a test that
#          still fails is red there, not green here.
#
# WHY COLUMN 5 EXISTS: AN XFAIL IS AN EXISTENCE CHECK ON A FAILURE, AND ANY
# FAILURE SATISFIES IT. Columns 1-4 are reconciled against cargo's `ok|FAILED`,
# which records THAT a test failed and never WHICH defect failed. A fixture that
# exercises six unimplemented features dies at whichever the parser meets first;
# a test can be blocked by a defect entirely upstream of the one it declares;
# and in both cases the row stays green while its reason text describes
# something that no longer happens. Measured the first time this column existed:
# 8 of the 43 rows below were failing for a reason other than the one their
# `#[ignore]` named. Column 5 is matched against the output cargo already
# captures for every failing test, and a mismatch is reported as
# DEBT_DIAGNOSTIC — distinctly from a row that fails for its named reason.
#
# The column is a MEASUREMENT, not a proof that the reason is the right one: a
# substring copied out of a run is as authoritative as the reason text a
# reviewer reads, and no more.
#
# It is NOT as authoritative as the owner column beside it, which is what this
# comment used to claim. The owner is checked against a SECOND inventory — the
# `#[ignore]` reason must name the same milestone, or the run reports DEBT_OWNER
# — while this column is checked against nothing but the run it was copied from,
# and the report prints the observed string when a row misses, so pasting it
# back into column 5 is the cheapest thing a hurried author can do. Review of
# the reason text is the whole boundary here. What the column buys is that the
# reason and the run cannot drift apart in silence.
#
# PAYING A DEBT IS A TRANSITION, NOT A DELETION. Delete the row and the test is
# an UNDECLARED_DEBT; delete the test and the row is DEBT_MISSING. Deleting both
# is an edit to a reviewed inventory that removes a named debt by name — the
# same authorisation boundary scripts/conformance.sh states about itself. This
# file cannot tell an honest reclassification from an evasive one. What it
# guarantees is that the evasion has to be written down.
#
# The reason text is NOT duplicated here on purpose: it lives in the #[ignore]
# attribute, which is the thing a reader edits, and a second copy would drift.
# The owner IS duplicated on purpose, because the duplicate is cross-checked.
#

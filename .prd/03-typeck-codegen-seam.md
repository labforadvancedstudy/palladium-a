## 라운드가 줄지 않은 이유

반려 사유를 모양별로 묶으면 세 가지가 반복된다.

1. **코드젠이 타입을 다시 추론한다.** 체커는 모든 정수를 `i64`로 기록하므로(#82), `u32` 값을
   제네릭에 넘기면 코드젠이 C 철자에서 폭을 되찾아 인스턴스를 고른다. 되찾는 규칙이 값의
   경로(파라미터, `let` 복사, 참조 너머 읽기, 필드, 배열 원소, 대입 뒤)마다 따로 있고, 한
   경로를 고치면 옆 경로의 틀린 값이 드러났다 (#86 라운드 2–8).
2. **제네릭 본문은 체커가 한 번도 완전히 검사하지 않는다.** 그래서 #88은 본문을 다시 걸으며
   타입을 "복구"하는 코드를 쌓았고, 복구가 틀리면 맞게 돌던 프로그램을 거부하고(잃은 실행),
   복구를 포기하면 참조 검사가 빠졌다. 라운드 3–7이 이 둘 사이를 오갔다.
3. **C 이름을 문자열로 조립한다.** #89는 비교 검사를 넣다가 이름 충돌을 건드렸고, 접두사
   추가(10차) → 단사 인코딩(11차) → 중첩 시 지수 팽창 수정(12차)으로 이어졌다. 12차 직전
   팁은 150바이트 소스에서 572 MiB의 C를 방출했다.

세 모양 모두 원인이 같다: 체커와 코드젠 사이에 **타입이 확정된 중간 표현이 없다**
(`02-architecture.md` "경계에서 실측된 사실").

## 같은 경계에서 함께 발견된 결함

시리즈 범위 밖이라 고치지 않고 재현 프로그램만 남겼다 (`research/found-defects/`, 재현 72개를
유닛별 문서 6개로 묶음). 유닛 코더가 측정해 남긴 것이고 이 문서를
쓰면서 다시 돌리지는 않았다. 수정 커밋이 없으므로 main `f2d1dd3`에 그대로 있다고 본다.

| 종류 | 예 |
|---|---|
| 조용히 틀린 값 | 공유 차용 `&s`를 `&mut` 파라미터에 넘기면 불변 바인딩이 써진다 · `&P`로 받은 값에 `&mut self` 메서드가 호출된다 · `let mut q = p`가 `&mut` 파라미터를 복사해 쓰기를 잃는다 · 옵티마이저가 `!(x == y) == z`에서 `z`를 버린다 · `u32`에 리터럴을 더하면 `long long`으로 계산된다 |
| gcc 실패 | 참조 파라미터의 `*p` · 지역 참조를 통한 필드 접근 · 선언되지 않은 타입 이름 수용 · struct 필드·enum variant 중복 수용 · 제네릭 본문에서만 불린 제네릭이 방출되지 않음 |
| 내부 오류(ICE) | `let r = &t; f(r)` 재차용 · 제네릭 본문의 배열·튜플 주석 |

## 결정이 필요한 것

| 선택지 | 내용 | 비용 근거 |
|---|---|---|
| A. 이슈 단위로 계속 | 남은 3유닛을 같은 방식으로 닫고 다음 이슈로 | 경계 유닛당 7–12 라운드, 라운드당 게이트 60분 이상 |
| B. 경계를 먼저 고친다 | 체커가 모든 식의 C 타입을 확정해 넘기고 코드젠은 인쇄만 하도록 재구성한 뒤 이슈 재개 | M3(traits·generics)가 같은 경계를 가장 크게 넓힌다. 그 전에 하지 않으면 A의 비용이 M3 내내 반복된다 |
| C. 표면을 줄인다 | 증명된 부분집합 밖은 전부 이름 붙여 거부 | 이미 리뷰 규칙("추측보다 이름 붙인 거부")이 이 방향이다. 잃는 것은 지금 우연히 도는 프로그램 |

권고: **B, 그동안의 규칙은 C.** 세 차별점(effects·totality·regions)은 전부 타입 판정이라
타입이 확정된 중간 표현을 어차피 요구한다. B는 M5–M7의 선행 작업이기도 하다.

덧붙이는 제안: **외부 오라클.** 반려의 다수는 "조용히 틀린 값"이었고 사람이 아니라 리뷰어
3명이 매 라운드 손으로 찾았다. Palladium의 현재 표면은 Rust의 부분집합에 가깝다. 공통
부분집합의 프로그램을 생성해 `pdc`와 `rustc`의 출력을 비교하는 차등 시험을 두면 이 종류를
기계가 찾는다. 측정된 것이 아니라 제안이다.
